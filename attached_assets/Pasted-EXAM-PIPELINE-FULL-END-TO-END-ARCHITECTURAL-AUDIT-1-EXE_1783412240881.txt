EXAM PIPELINE — FULL END-TO-END ARCHITECTURAL AUDIT
1. EXECUTIVE SUMMARY
The Sage exam pipeline consists of nine identifiable stages: curriculum ingestion, question extraction, question storage, answer key generation, exam publishing, attempt creation, grading, weakness analysis, and flashcard generation.

Seven of those nine stages are implemented and functional. The pipeline is architecturally coherent, well-structured, and handles edge cases (OCR fallback, quota exhaustion, DB recovery, Jaccard dedup) with genuine sophistication.

One stage is entirely absent: Answer Key Enrichment — the process of giving MCQ questions a correctAnswer when that answer is not embedded in the source PDF. This is not a runtime bug. It is a missing pipeline stage.

One stage is architecturally naïve in its safety gates: Publishing — an exam with zero gradeable questions can be made visibility='public' and served to students with no validation warning.

Every downstream component — grading, weakness tracking, flashcard backs — degrades silently when correct_answer is NULL. Nothing throws. Nothing warns. The system produces a completed, scored, analyzed exam that is numerically meaningless.

3. PHASE-BY-PHASE TRACE
PHASE 1 — CURRICULUM INGESTION ✓ COMPLETE
Entry Point: POST /api/curriculum/upload → routes/curriculum.ts

Middleware Stack (in order):

requireAuth — Firebase JWT verification
rateLimit('pdf_upload') — token-bucket rate limiter (PostgreSQL-backed)
multer — multipart/form-data, temp storage at data/tmp/
PDF validator — magic bytes check + SHA-256 dedup + malicious pattern scan
PDF Storage (dual-write):

Layer	Path / Table	Implementation
Disk	data/pdfs/{docId}.pdf	curriculumStorage.getPdfPath()
PostgreSQL	public.curriculum_pdfs (bytea)	pdfPersistence.savePdfToDb()
At restart: if disk file missing, restores from curriculum_pdfs table.

OCR Pipeline (pdfExtractor.ts):

Stage 1: Native text-layer extraction (pdf-parse)
         ↓ if empty/garbled
Stage 2: Form-feed split (physical page boundaries)
         ↓ if still poor
Stage 3: Virtual page split (heuristic page markers)
         ↓ if still poor
Stage 4: Image OCR — pdftoppm → PNG → Gemini gemini-2.5-flash inline
         ↓
         Raw text per page
Supports resume (startFromPage), QuotaExhaustedError bailout, partial status + appendChunks.

Chunk Generation (chunker.ts):

PAGES_PER_CHUNK = 4
MAX_CHUNK_CHARS = 5000 — sub-split at whitespace if exceeded
Every CurriculumChunk carries: {id, docId, country, grade, subject, chapter, pageRange, chunkIndex, content, contentNormalized, keywords, embedding}
Embeddings:

Model: text-embedding-004 via embeddingService.ts
Storage: embedded directly in chunk JSON files on disk + curriculum_chunks.embedding JSONB
Timing: async post-ingestion, also backfilled at startup (generateMissingEmbeddings())
Vector Index: No standalone vector DB (Pinecone/pgvector/etc). Hybrid scoring computed at query time in searchChunks(): cosine similarity on stored embeddings + trigram keyword weight (×25).

Curriculum Registry:

Disk: data/curriculum/index.json — array of CurriculumDocument objects
PostgreSQL: curriculum_documents table, mirrored via curriculumPersistence.upsertDocMetaToDB()
Key document fields: {id, filename, subject, grade, country, track, visibility, status, docType, ownerId}
Search Cache: Redis, key = search:{userId}:{subject}:{hash}, TTL = cache.TTL.SEARCH. X-Cache: HIT/MISS header on every response.

Final Searchability: GET /api/curriculum/search → searchChunks(query, filters) in curriculumStorage.ts Chunks become searchable once embeddings are generated (async — may lag upload by seconds to minutes depending on chunk count).

PHASE 2 — QUESTION EXTRACTION ✓ COMPLETE (with data-quality gap)
Triggers (4 paths):

Trigger	Location	When
Upload pipeline	curriculumQueue.ts	After OCR completes for docType='exam'
Startup sync	index.ts syncAndRecoverExams()	Pending/error/stuck exams on boot
Admin manual	routes/admin.ts	Explicit admin POST
On-demand	routes/exam.ts	Exam requested but questionCount=0
Call Chain:

triggerQuestionExtraction(docId)
  → loadChunks(docId)           — reads chunk JSON files from disk
  → compressFillerDots(chunk)   — strips long .... / ____ runs (token saving)
  → buildPrompt(chunkText, examTitle)  — per chunk
  → callGemini(prompt)          — gemini-2.5-flash, maxOutputTokens=32768
  → parseResponse(raw)          — JSON.parse with regex fallback
  → [REPEAT per chunk, 3 passes]
  → normalizeAll(allParsed)     — Arabic normalization (tatweel, kashida, invisible chars)
  → deduplicateEnhanced(normalized, { discriminatorField: 'correctAnswer' })
     — Jaccard threshold: 0.80
  → analyzeCoverage(chunkDiags, deduped.length)  — LOW_EXTRACTION_COVERAGE warn
  → analyzeOcrText(allChunkText)  — OCR quality score 0-100
  → computeExtractionScore(...)   — composite score 0-100, grade A-F
  → saveQuestions(toInsert)        — INSERT to PostgreSQL
  → saveQuestionsToFile(examId, toInsert)  — JSON snapshot
  → upsertExamRecord({...status:'done', questionCount})
Gemini Prompt (Arabic, verbatim):

أنت نظام استخراج أسئلة امتحانات للمحتوى التعليمي العربي.
استخرج كل الأسئلة من نص الامتحان التالي.
أعد مصفوفة JSON فقط. كل عنصر يجب أن يكون:
{
  "question": "<نص السؤال كاملاً بالعربي>",
  "questionType": "mcq" | "true_false" | "short_answer" | "essay" | "calculation",
  "options": ["أ) ...", "ب) ...", "ج) ...", "د) ..."] أو null للأسئلة المقالية,
  "correctAnswer": "<الإجابة الصحيحة أو null إذا لم تذكر في النص>",
  "explanation": "<الشرح إن وُجد أو null>",
  "topic": "<الموضوع إن وُجد>",
  "chapter": "<الفصل إن وُجد>",
  "difficulty": "easy" | "medium" | "hard" | null
}
Key phrase: "null إذا لم تذكر في النص" — null if not mentioned in the text. This is architecturally correct for PDFs that embed answer keys inline. It is architecturally incomplete for standalone question papers (the standard format for Sudanese national exams).

Pass 2	LOW_EXTRACTION_COVERAGE flag	buildRetryPrompt() — aggressive, includes table handling

Startup recovery path (runs every restart):

syncAndRecoverExams()
  → listExamRecords (all)
  → filter: status IN ('pending','extracting','error') OR (status='done' AND questionCount=0)
  → for each pending:
      if hasQuestionsSnapshot(examId):

What examGenerator.ts does (and why it does not fill this gap): examGenerator.ts generates synthetic exam questions from curriculum chunks. It prompts Gemini to produce {question, options, correctAnswer, explanation} in one pass — Gemini invents questions AND their answers simultaneously from curriculum text. This only applies to generated (synthetic) exams. It does not retroactively enrich real extracted exam questions that arrived with correctAnswer = null.

PHASE 5 — PUBLISHING ⚠️ PARTIAL
exam_records state machine:

pending → extracting → done
                    ↘ error
Visibility values: 'private' (default) | 'public'

listExamRecords() for non-admin students:

SELECT * FROM exam_records
WHERE visibility = 'public'
   OR (visibility = 'private' AND owner_id = :userId)
No filter on extraction_status — an exam with status='error' that is also visibility='public' will appear in student listings.

No filter on question_count — an exam with question_count=0 and visibility='public' will appear.

No filter on correct_answer completeness — no concept of "gradeable" exists at the publishing layer.

POST /start guard (access check only):

if (record.visibility === 'private' && record.ownerId !== uid && !isAdmin(req.user!)) {
  return 403;
}
// No check: record.extractionStatus !== 'done'
// No check: record.questionCount > 0
// No check: questions have non-null correctAnswer
Can an exam with all-null correctAnswer be published and attempted?

Yes. Confirmed live. Biology 2024: visibility='public', extraction_status='done', question_count=50, correct_answer=NULL for all 50 rows. Students can start, answer, and submit this exam. They receive a score of 0.00 regardless of their actual answers.

PHASE 7 — WEAKNESS ENGINE ✗ SILENTLY POISONED
Trigger: updateWeaknessFromAttempt(attemptId, studentId) — fire-and-forget, immediately after gradeAttempt() completes.

Data flow:

// 1. Load all graded answers
const answers = getAnswersByAttempt(attemptId)

weaknessScore computation:

weaknessScore = 1 - ts.score   // = 1 - 0.0 = 1.0 for every topic
Result: Every topic in every exam the student has taken shows weaknessScore = 1.0 (maximum weakness). A student who correctly answers every question still appears to have 0% proficiency in every topic. The weakness dashboard becomes noise: it reports everything as catastrophically weak, which is identical to reporting nothing.

No floor, no null-check, no "data integrity" flag. The engine processes whatever isCorrect values it receives, faithfully computing a score from poisoned input.

PHASE 8 — FLASHCARDS ⚠️ DEGRADED
Two flashcard generation paths:

Path A — AI Chat (flashcardGenEngine.ts): Triggered by AI tutor responses. Extracts "key concepts" from chat context. Completely independent of exam correctAnswer. Not affected by the answer-key gap.

Path B — Exam Wrong Answers (routes/examSolver.ts /flashcards):

GET /api/exams/solve/:attemptId/flashcards
const wrong = answers.filter((a) => a.isCorrect === false)
// ↑ With null answers: all 10 MCQ answers qualify as "wrong"
for each wrong answer:
  flashcard = {
    front:         question.question,
    back:          question.correctAnswer    // NULL
                   ?? question.explanation  // NULL (rarely populated)
                   ?? answer.aiFeedback     // NULL (deterministicGrader skipped AI)
                   ?? 'راجع الشرح',         // ← always falls through to this
    category:      question.topic ?? question.chapter ?? question.subject ?? 'عام',
    source:        'exam_question',
    studentAnswer: answer.studentAnswer,
    aiFeedback:    null,
  }
Impact:

Every MCQ question produces a flashcard (10/10, not just wrong answers)
Every flashcard back = 'راجع الشرح' (Arabic: "Review the explanation")
Zero learning content in the back
SM-2 scheduler still runs on these cards — repetition intervals are computed and stored, but the student is reviewing blank cards
Daily limit: MAX_FLASHCARDS_PER_DAY = 10. With 10 "wrong" answers per exam, the limit is consumed on the first exam session, blocking AI-chat flashcards for the rest of the day.

The first missing architectural stage is between Phase 2 (Extraction) and Phase 3 (Storage):

Answer Key Enrichment — the process of deriving, accepting, or verifying the correctAnswer for every MCQ question when the exam source PDF does not contain an answer key.

This is not a bug in any existing component. Every existing component behaves correctly:

Gemini correctly returns null when the answer is not in the text
The storage layer correctly preserves null
The grader correctly short-circuits on null
The code comments even acknowledge the possibility: "correctAnswer": "<الإجابة الصحيحة أو null إذا لم تذكر في النص>"
The problem is that the pipeline was designed with a silent assumption that exam PDFs would always contain their own answer keys. That assumption is false for this domain.

11. FINAL
The Sage exam pipeline is architecturally sound in structure but incomplete in data contract.

It was designed and built for exam PDFs that self-contain their answer keys. Sudanese national exam papers do not. Every component downstream of extraction operates on the silent assumption that correct_answer is populated. None verify it. None refuse to proceed without it. The system completes every operation — extraction, storage, grading, weakness, flashcards — and at every step produces a result that is internally consistent, structurally valid, and numerically meaningless.

The first missing architectural stage is Answer Key Enrichment: a mechanism by which, after extraction produces correct_answer = null for MCQ questions, those answers can be supplied — whether by uploading a separate answer key PDF, by an admin manually specifying answers, or by a RAG pipeline that reads curriculum text, considers each question and its options, and identifies the correct option from the educational content.

Until that stage exists, the exam grading subsystem cannot function for the domain it was built to serve.
